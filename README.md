# ai-place-mate-prd-to-srs

**AI 장소 큐레이션 PRD v0.1** 을 **SRS 문서**로 변환하는 작업 저장소입니다.

---

## 1. 작업 목표

이 저장소의 목표는 **PRD를 예시 SRS 문서와 동일한 포맷의 SRS로 변환**하는 것입니다.

### 1.1 하는 일

> **기준 템플릿은 `[SRS 문서] AD-Core-Platform (한글).md` 하나입니다.**

`ai-place-prd-v0.1.html` 에 담긴 내용을, 예시 SRS 문서가 이미 쓰고 있는 섹션 구성·표 스키마·ID 체계·서술 톤으로 옮겨 적습니다. 도메인만 다를 뿐(광고 플랫폼 → 장소 큐레이션), 문서의 **뼈대는 예시 문서를 그대로 따릅니다.**

### 1.2 하지 않는 일

**ISO/IEC/IEEE 29148:2018 표준을 전부 만족하는 풀 스펙 SRS를 쓰는 것이 목표가 아닙니다.**

표준이 요구하는 전체 섹션(운영 개념, 생명주기 요구사항, 검증 계획 전문, 요구사항 속성 완전 집합 등)을 빠짐없이 채우는 방향으로 문서를 부풀리지 않습니다. 예시 SRS가 다루지 않은 영역은, 아래 3항의 확장 규칙에 해당하지 않는 한 **쓰지 않습니다.**

### 1.3 확장 규칙 — 예시 문서 범위를 넘는 PRD 내용의 처리

PRD에는 예시 SRS의 7개 섹션 어디에도 자연스럽게 들어가지 않는 내용이 있습니다. 이런 내용은 버리지 않되, 임의의 형식으로 덧붙이지도 않습니다.

**해당 부분에 한해서만 ISO/IEC/IEEE 29148:2018 의 표준 포맷 구성을 따라 섹션을 확장해 작성합니다.**

즉 세 갈래로 처리합니다.

| 상황 | 처리 |
| --- | --- |
| 예시 SRS에 대응 섹션이 있음 | 예시 포맷 그대로 채움 |
| 예시 SRS에 대응 섹션이 없음 | **그 부분만** 29148 표준 구성에 따라 섹션 신설 |
| PRD에 없는데 예시 SRS에는 있는 항목 | 억지로 만들지 않고 미정으로 표기 |

확장으로 신설한 섹션은 어느 표준 조항을 근거로 추가했는지 문서 안에 밝힙니다. 확장은 **최소 단위**로 합니다 — 한 문단을 넣기 위해 표준 전체 챕터를 끌어오지 않습니다.

## 3. 포맷 기준 — 예시 SRS의 골격

변환 결과물이 따라야 할 구성입니다.

```
1. 서론          1.1 목적 / 1.2 범위 / 1.3 정의·약어·축약어
2. 이해관계자     역할 · 담당 · 책임 표
3. 시스템 맥락 및 인터페이스   클라이언트 / 내부 서비스 / 외부 시스템
4. 구체적 요구사항  4.1 기능 요구사항 (REQ-FUNC-xxx)
                 4.2 비기능 요구사항 (REQ-NF-xxx)
5. 추적성 매트릭스  요구사항 ID ↔ 모듈 ↔ 구현 클래스 ↔ 테스트 케이스 ID
6. 부록          6.1 API 엔드포인트 / 6.2 데이터 모델 / 6.3 비즈니스 규칙 / 6.4 DB 스키마
7. 향후 개선 사항
```

요구사항 표의 열 스키마도 예시 문서를 그대로 씁니다.

`ID | 제목 | 출처 | 우선순위 | 유형 | 검증 방식 | 인수 기준 | 상태 | 담당자`

## 4. 입력 PRD 개요

- **제품:** AI 장소 큐레이션 — "조건을 말하면 근거가 붙은 세 곳이 온다"
- **북극성 KPI:** WEBD(주간 근거 기반 결정 완료 수) · 12주 목표 5,000건/주
- **기능 범위:** F1–F9 · Must 6 / Should 1 / Could 2
- **단계:** Phase 1 클로즈드 베타(수요 측) → Phase 2 오픈 베타(에이전트 제안)
- **유저 스토리:** US-1 ~ US-6, 각 AC마다 정량 임계치 보유
- **실험 설계:** E1 ~ E7

### 변환 시 유의점

PRD 기준선 대부분이 **가설(H)** 상태입니다. 모의 인터뷰 11건, 실제 로그 0건. PRD 스스로 "정확한 목표값 제시가 아니라 무엇을 측정하면 틀렸음을 알 수 있는지를 못 박는 것"이 목적이라고 밝히고 있습니다.

따라서 SRS의 **인수 기준** 칸에 이 수치들을 옮길 때는 확정 사양이 아니라 **Phase 0 이후 재설정 대상**임이 드러나게 표기합니다. (표기 방식 확정 필요)
