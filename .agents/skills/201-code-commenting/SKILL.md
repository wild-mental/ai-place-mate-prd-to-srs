# 주석

## 원칙

**코드가 무엇을 하는지는 코드가 말한다. 주석은 왜 그런지를 말한다.**

읽는 사람이 "이건 왜 이렇게 했지?" 하고 멈출 지점에만 쓴다.
줄마다 붙은 주석은 읽히지 않고, 코드가 바뀌면 거짓말이 된다.

## 쓸 가치가 있는 것

- **비직관적인 선택의 이유** — 더 단순해 보이는 방법을 왜 안 썼는지
- **제약에서 비롯된 코드** — "D-03으로 캐시 서버를 못 써서 `use cache`로 처리"
- **외부 시스템의 특이점** — 풀러가 DDL을 못 다룬다든지
- **의도적인 트레이드오프** — 성능을 위해 정규화를 포기했다든지
- **위험 경고** — 이 함수는 RLS를 우회한다, 범위는 여기까지다

## 쓰지 않는 것

| ❌ | 왜 |
| --- | --- |
| `// 사용자를 조회한다` (`getUser()` 위에) | 코드가 이미 말한다 |
| 주석 처리한 옛 코드 | git이 기억한다. 지운다 |
| `// TODO` 만 있고 근거 없음 | 이슈로 만든다 |
| 함수마다 붙는 형식적 JSDoc | 공개 API가 아니면 타입으로 충분하다 |

## 유지보수

- **쓸모없어진 주석은 즉시 지운다.** 틀린 주석은 없느니만 못하다
- 코드를 고치면 그 위 주석이 여전히 맞는지 본다
- 주석이 길어지면 설계가 복잡한 신호다. 주석 대신 구조를 고칠 수 있는지 본다

## 언어

- 한국어로 쓴다. 이 저장소의 문서가 한국어다
- 요구사항·제약을 참조할 때는 ID를 적는다 (`REQ-NF-001a`, `D-07`) — 원천을 찾아갈 수 있다
