# AI 통합 규칙

SDK 사용법은 설치된 스킬 `ai-sdk`가 다룬다.
**이 문서는 이 프로젝트가 AI를 어떻게 쓰기로 했는지**를 적는다.

## 대전제 — LLM은 폴백이다

자연어 질의 파싱은 **결정론 파서가 먼저** 처리한다. LLM은 그것이 실패한 입력만 받는다 (ADR-T02).

```
사용자 질의
   ↓
파싱 캐시 조회 ──── 히트 ──→ 반환          목표 히트율 ≥ 60% (REQ-NF-002b)
   ↓ 미스
결정론 파서 ─────── 성공 ──→ 반환 + 캐시   목표 흡수율 ≥ 70%
   ↓ 실패
Gemini 구조화 출력 ─────────→ 반환 + 캐시
```

**이 순서를 뒤집으면 안 되는 이유는 두 가지다.**
첫째, LLM 왕복이 파싱 예산을 구조적으로 초과해 REQ-NF-001a(p95 ≤ 1,000ms)를 깬다.
둘째, 모든 질의를 LLM에 보내면 비용이 트래픽에 선형으로 붙는다.

응답 시간 기준도 경로별로 다르다 — 결정론 p95 ≤ 1,000ms, LLM 폴백 p95 ≤ 2,500ms.

## 모델 지정

- **모델 ID를 코드에 상수로 두지 않는다** (D-07). 환경 변수로만 지정한다
- 이유는 C-TEC-006이다 — 환경 변수만 바꿔 모델을 교체할 수 있어야 한다
- API 키는 `GOOGLE_GENERATIVE_AI_API_KEY`
- 프로바이더는 `@ai-sdk/google`

```ts
// ✅ 환경 변수로 주입
const model = google(process.env.AI_MODEL_ID!)

// ❌ 하드코딩 — D-07 위반
const model = google('gemini-3.7-flash')
```

## 구조화 출력

파싱 결과는 자유 텍스트가 아니라 **스키마가 있는 객체**여야 한다.

```ts
generateText({ model, output: Output.object({ schema }) })
```

- 스키마는 도메인이 소유한다. 프롬프트 옆에 인라인으로 두지 않는다
- 스키마 검증에 실패한 응답은 **버린다.** 부분 파싱해서 쓰지 않는다

## 실패 처리

LLM은 느려지고, 틀리고, 멈춘다. 셋 다 대비한다.

- **타임아웃을 건다.** 무한정 기다리면 사용자 요청이 함께 멈춘다
- 실패 시 사용자에게 보여줄 경로가 있어야 한다 — 구조화 입력 폼으로 유도하는 등
- 재시도는 **멱등한 경우에만**. 과금되는 호출을 무턱대고 재시도하지 않는다
- 실패를 삼키지 않는다. 관측 가능하게 남긴다 (`src/lib/observability.ts`)

## 캐시

- 파싱 캐시는 **정규화한 질의**를 키로 쓴다. 공백·어순 차이로 캐시가 갈라지면 히트율이 죽는다
- 캐시 계층은 `use cache` 또는 PostgreSQL이다. **캐시 서버를 두지 않는다** (D-03)

## 프롬프트

- 프롬프트는 코드와 함께 버전 관리한다. 런타임에 외부에서 주입하지 않는다
- 사용자 입력을 프롬프트에 그대로 이어붙이지 않는다 — 구조화된 자리에 넣는다
- 프롬프트를 바꾸면 **파싱 캐시를 무효화**한다. 안 그러면 옛 결과가 계속 나온다

## 안티패턴

| ❌ | 왜 |
| --- | --- |
| 모든 질의를 LLM에 전달 | NFR 초과 + 비용 선형 증가 |
| 모델 ID 하드코딩 | D-07 위반 — 교체 불가 |
| 스키마 없는 자유 텍스트 파싱 | 다운스트림이 방어 코드로 뒤덮인다 |
| 타임아웃 없는 호출 | 사용자 요청이 함께 멈춘다 |
| 프롬프트 변경 후 캐시 유지 | 옛 결과가 계속 반환됨 |
