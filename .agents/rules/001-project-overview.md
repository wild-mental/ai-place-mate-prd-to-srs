# PROJECT OVERVIEW: AI-Place-Mate

## Vision

모임 장소를 정하는 일은 지금도 사람이 손으로 한다. 참석자에게 조건을 묻고, 지도에서 중간 지점을 찍고,
후보를 몇 개 찾아 링크를 붙여 단톡방에 던진다. **AI-Place-Mate는 이 반복 노동을 자동화한다.**
자연어 한 줄("강남에서 6명, 조용한 데")로 조건을 받아 후보를 추천하고, 근거를 함께 제시한다.

## Core Features

- **자연어 질의 파싱** — 조건(지역·인원·분위기·예산)을 구조화한다. 결정론 파서가 먼저 처리하고, 실패분만 LLM이 받는다.
- **후보 추천과 랭킹** — 조건에 맞는 장소를 점수화해 정렬한다.
- **근거 제시(Evidence)** — 왜 이 장소인지 리뷰·속성에서 근거를 뽑아 붙인다. 추천만 하고 끝내지 않는다.
- **중간 지점 매칭** — 참석자 출발지에서 이동 부담이 균형 잡히는 지점을 찾는다.
- **합의(Agreement)** — 후보를 공유하고 참석자 반응을 모아 결정을 돕는다.
- **예약 연동** — 결정된 장소의 예약 흐름으로 잇는다.

## Target Audience

- **Primary:** 3~10명 규모 모임의 **주선자**. 장소 선정 부담을 혼자 지는 사람이다.
- **Secondary:** 모임 **참석자**. 조건을 내고 후보에 반응한다.

## Project Goals & Success Metrics

권위 있는 목표는 SRS에 있다. 여기 적은 것은 개발 판단에 자주 쓰이는 요약이다.

- **TTV** — 질의 입력에서 후보 확인까지 체감 지연을 낮게 유지한다 (결정론 경로 p95 ≤ 1,000ms).
- **근거 신뢰** — 추천에는 항상 근거가 붙는다. 근거 없는 추천은 기능 미달로 본다.
- **비용 통제** — LLM 호출은 폴백이다. 파싱 캐시 히트율 ≥ 60%를 유지해 호출 자체를 줄인다.

## Project Philosophy

- **문서가 먼저다.** 요구사항은 SRS, 구현 방식은 설계 문서, 할 일은 태스크 문서에 있다.
  코드가 문서와 어긋나면 **어긋난 쪽을 고치는 게 아니라 무엇이 옳은지 먼저 정한다.**
- **제약을 우회하지 않는다.** C-TEC-001~007은 발주 측 확정 사항이다. 불편하면 §15 충돌 대장에 적고 논의한다.
- **근거를 남긴다.** 왜 그렇게 했는지가 코드에 남지 않으면 다음 사람이 되돌린다.
