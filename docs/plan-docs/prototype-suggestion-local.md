### 이 안의 전제 하나

**디자인 태스크(`UX-*`)와 UI 태스크를 한 사람의 같은 작업으로 합친다.** 화면 코드가 곧 화면 정의의 초안이 된다.

- **얻는 것** — 30 person-day짜리 디자인 레인이 사라진다. 5일 안에 화면이 선다.
- **잃는 것** — 핸드오프 가능한 디자인 산출물이 남지 않는다. **`UX-*` 이슈는 그대로 열려 있다** (§7).

## 5. 디렉터리 — 지금 지켜야 나중에 안 되돌린다

SRS §14.1 구조를 **처음부터** 쓴다. 파일 위치만 지키면 본 개발이 이 코드를 그대로 이어받는다.

```
ai-place-mate/
├─ app/
│  ├─ layout.tsx
│  └─ (search)/
│     ├─ page.tsx              ← UX-003 조건 입력
│     └─ results/page.tsx      ← UX-006 · UX-004 · RNK-003 결과·상태
└─ src/
   ├─ components/ui/           ← shadcn 설치본. 직접 만들지 않는다 (D-08)
   ├─ lib/                     ← 비워 둔다
   ├─ modules/                 ← 비워 둔다. 본 개발이 채운다
   └─ mocks/
      ├─ types.ts              ← 화면이 소비하는 타입 한 겹. CTR-001로 교체될 자리
      ├─ top3.ts               정상 / 근거 누락 / 2건 / 0건
      ├─ parse.ts              결정론 / 폴백 / 실패
      └─ fixture-switch.ts     ← 프로토타입 전용. 본 개발 진입 시 삭제
```

### 두 가지 규칙

- **화면은 `src/mocks/types.ts` 만 본다.** 픽스처 리터럴을 컴포넌트가 직접 물지 않는다. `CTR-001`이 확정되면 이 파일 하나를 계약 타입으로 갈아 끼우고 화면은 그대로 둔다.
- **`fixture-switch.ts` 는 이 프로토타입에서 유일하게 버리는 코드다.** SRS에 없는 개발용 장치이므로 `src/mocks/` 밖으로 나가지 않게 하고, 본 개발 진입 시 삭제한다.

## 9. 이 범위에서 명시적으로 하지 않는 것

혼동을 막기 위해 적는다. 아래를 했다고 말할 수 없다.

- **성능을 검증하지 않는다** — 픽스처는 지연이 없다. REQ-NF-001a/001b/004는 `TST-010`이 측정한다
- **접근성을 검증하지 않는다** — 대비 확인은 `UX-001` 본 착수에서
- **계측을 넣지 않는다** — `top3_rendered` · `card_expanded` 는 자리도 만들지 않는다
- **테스트를 쓰지 않는다** — 눈으로 판정한다. 렌더 테스트는 `RNK-003` 본 착수에서
- **데이터를 읽지 않는다** — DB·AI·인증 어느 것도 붙지 않는다
