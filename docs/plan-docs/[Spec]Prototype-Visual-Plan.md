## 1. 화면 인벤토리 <!-- T1 -->

### 1.1 상태 8종

**상태는 화면이 통째로 갈리는 단위다.** 한 번에 하나만 성립한다.

| # | 상태 | 경로 | 무엇을 보는가 | 근거 |
| --- | --- | --- | --- | --- |
| **S1** | 조건 입력 | `/` | 필수 입력 필드 0개로 검색이 되는가 | US-2 AC3 · `UX-003` |
| **S2** | 로딩 스켈레톤 | `/results?fixture=loading` | 결과 카드 골격이 먼저 보이는가 (흰 화면 없음) | REQ-NF-001b · `UX-003` |
| **S3** | Top-3 정상 | `/results?fixture=ok` | 근거 4항목이 세 카드에 모두 보이는가 | US-3 AC1 · `UX-006` |
| **S4** | 90일 경고 · 가격 확인 필요 | `/results?fixture=stale` | 경고가 붙는가 · 예상가 대신 '가격 확인 필요'가 뜨는가 | US-3 AC2 · US-1 AC6 · `UX-006` |
| **S5** | 후보 2건 | `/results?fixture=two` | 3건을 억지로 채우지 않는가 | SRS §6.3-3 · `UX-004` |
| **S6** | 결과 0건 | `/results?fixture=zero` | 사유와 다음 행동이 있는가 | SRS §6.3-6 · `UX-004` |
| **S7** | 파싱 실패 폴백 | `/results?fixture=parse-fail` | 구조화 필터로 갈아타고 해석 못 한 표현이 그대로 보이는가 | US-1 AC5 · `UX-004` |
| **S8** | 오류 | `/results?fixture=error` | 시스템 탓을 사용자에게 돌리지 않는가 | `UX-004` 톤 규약 |

### 1.2 고지 배너 3종

**배너는 상태가 아니라 요소다.** 결과가 정상으로 나온 화면 위에 얹히며, **둘 이상이 동시에 뜰 수 있다.**

배너의 존재 이유는 **시스템이 사용자 요청을 그대로 처리하지 않고 조정했을 때 그 사실을 밝히는 것**이다. 조정해 놓고 밝히지 않으면 근거를 빼는 것과 같다 — PRD가 세 건 모두에 `표기율 100%` 를 걸어 둔 이유다.

| ID | 문구 (초안 · T3에서 확정) | 조정 내용 | 위치 | 근거 |
| --- | --- | --- | --- | --- |
| **N1** | 찾는 메뉴가 없어 유사 메뉴로 대체했습니다 | 메뉴 색인 미스 → 유사 메뉴로 검색 | 목록 **상단** | US-2 AC2 |
| **N2** | 반경을 3km로 넓혔습니다 | 1km 내 0건 → 1회 자동 확대 | 목록 **상단** | US-2 AC4 (`표기율 100%`) |
| **N3** | 예산 초과 N곳은 제외했습니다 | 인당 예상가 상한 초과 매장 제외 | 목록 **하단** | US-1 AC2 (`오탐률 ≤ 3%`) |

**규칙**

- **N1·N2는 스택으로 쌓는다.** 둘 다 걸린 상황이 실재한다 (메뉴도 없고 반경도 넓힘).
- **배너는 오류가 아니다.** 경고·오류 색을 쓰지 않는다. 색 지정은 T4에서 한다.
- **얹히는 상태** — S3 · S4 · S5. 상태 S6(0건) · S7(폴백) · S8(오류)에는 얹히지 않는다.
- **N3은 하단**이다 — 결과에 대한 각주이지 결과의 전제가 아니다.

### 1.3 확인용 프리셋

상태 8종 외에 **배너를 보기 위한 프리셋 1개**를 둔다.

| 키 | 내용 |
| --- | --- |
| `/results?fixture=notices` | S3(정상 3건) 위에 **N1 · N2 동시 + N3 하단** |
| `/results?fixture=ok&selected=p2` | **선택 상태** — 카드 슬롯 ⑥이 닫힌 화면 |

> **선택은 상태가 아니라 파라미터다.** `fixture` 목록을 늘리지 않는다 — 어느 결과 화면에서도 선택이 성립하기 때문이다.

> **잔여 논점 (토픽 아님 · 기록만)** — PRD US-2 AC4는 `결과 0건 종료 0회` 를 목표로 두고 인접 카테고리 대체까지 요구하는데, SRS REQ-NF-007은 `빈 결과 반환률 ≤ 2%` 로 0이 아닌 예산을 잡는다. 모순이 아니라 **목표와 예산의 차이**다. 프로토타입은 S6(결과 0건) 화면을 유지한다 — 2%가 0%가 아니므로 화면이 필요하다.

## 2. 후보 카드 정보 구조 <!-- T2 -->

### 2.1 카드 3장 + 하단 비교표

**세로로 쌓은 카드 3장 아래에 비교표 1개**를 둔다. 카드는 후보를 이해하는 곳이고, 비교표는 셋을 나란히 놓는 곳이다.

```
┌──────────────────────────────┐
│ ① 1  가마솥국밥      1.8~2.2만 │  순위 · 매장명 · 인당 예상가 범위
│ ② "1인석 6석 · 21시까지 영업"   │  선정 이유 1줄
│ ③ [1인석] [늦은영업] [국밥]     │  근거 속성
│ ④ ⚠ 확인 90일 경과            │  경고 (해당 시)
│ ⑤ 8/12 · 매장 등록            │  확인 일자 · 확인 주체
│ ⑥ [ 이 곳으로 정하기 ]         │  선택 행위
└──────────────────────────────┘
   … 2번 · 3번 카드도 같은 순서 그대로

【비교】
        1번    2번    3번
인당가   1.8만  2.1만  확인필요
대표    국밥   돈까스  파스타
상황    1인석  조용   콘센트
확인    8/12   8/20   5/03 ⚠
```

**슬롯은 6개이고 순서가 고정이다.** 카드마다 같은 항목이 같은 자리에 있어야 눈이 세 장을 훑을 수 있다.

| 슬롯 | 내용 | 근거 4항목 | 없을 때 |
| --- | --- | --- | --- |
| ① | 순위 · 매장명 · **인당 예상가 범위** | — | 가격 부실 시 **'가격 확인 필요'** (US-1 AC6) |
| ② | **선정 이유 1줄** | ① | 카드가 될 수 없다 (§6.3-2) |
| ③ | **근거 속성** (칩 나열) | ② | 카드가 될 수 없다 |
| ④ | ⚠ 확인 90일 경과 | — | 해당 없으면 슬롯 자체를 비운다 |
| ⑤ | **확인 일자 · 확인 주체** | ③④ | 카드가 될 수 없다 |
| ⑥ | **선택 행위** — `이 곳으로 정하기` / 선택 후 `이 곳으로 정했습니다` | — | **여정이 읽기에서 끝난다** |

- **인당 예상가는 범위로만** 쓴다 — `1.8~2.2만` 형식. 범위 폭 ≤ ±20% (US-1 AC1)
- **④는 조건부 슬롯**이다. 경고가 없으면 빈 줄을 남기지 않는다
- 예산 초과로 뺀 매장은 카드가 아니라 **배너 N3**로 요약한다 (§1.2)

### 2.1.1 슬롯 ⑥이 왜 있어야 하는가

PRD의 북극성 WEBD는 **"조건 입력 → Top-3 수신 → 1곳 선택까지 완주한 세션"** 으로 정의되고, §2.2 분기 02(Top-3 내 선택률 45%)는 **"이 제품의 생사"** 로 적혀 있다. 선택할 자리가 없으면 화면은 읽기에서 끝나고 여정의 마지막 칸이 빈다.

**선택의 귀결과 선택 행위를 구분한다.** 예약·결제(`UX-015`)·공유 카드(`UX-010`)는 이 프로토타입 범위 밖이지만, 그것들은 선택의 *귀결*이다. 선택 *행위* 자체는 범위 안이며 화면으로 성립해야 한다.

선택은 `?selected=<후보 id>` 로 표현한다. 선택된 카드에 테두리를 두고 슬롯 ⑥을 `이 곳으로 정했습니다` 로 바꾸며, 헤더에 `1곳 선택함 · <매장명>` 을 남긴다. **상태를 늘리지 않는다** — 어느 결과 화면에서도 선택이 성립하기 때문이다.

### 2.2 비교표 — 390px에서 가로 스크롤 없이

축 4개는 PRD가 확정한 것을 그대로 쓴다 — **인당가 · 대표메뉴 · 상황속성 · 확인일자**.

| 항목 | 규칙 |
| --- | --- |
| 열 구성 | 라벨 열 **고정 56px** + 후보 3열 **등분** (390 − 좌우 여백 32 − 56 = 302 ÷ 3 ≈ 100px) |
| **값 축약** | **최대 5자.** 넘으면 말줄임. `~1.8만` `확인필요` `국밥` `1인석` `8/12` |
| 인당가 표기 | 범위 **상한** 기준이며 앞에 `~` 를 붙인다. 카드는 `1.1~1.4만`, 표는 `~1.4만` — `~` 가 없으면 같은 값의 다른 표기로 읽혀 C2의 예산 역산이 어긋난다 |
| 가로 스크롤 | **금지.** 열이 넘치면 값을 더 줄인다 |
| 90일 경과 | 확인일자 셀에 `⚠` 를 덧붙인다 |
| 후보 2건(S5) | **2열로 줄인다.** 빈 열을 만들지 않는다 |

> 값 축약이 이 표의 성패다. 축약 규칙이 없으면 폰트가 작아지거나 가로 스크롤이 생기고, 둘 다 비교를 포기하는 결과가 된다.

### 2.3 확인 주체 — 값 4종

v0.1에 실재하는 네 경로와 1:1이다. **이 넷 외의 값을 만들지 않는다.**

| 값 | 어디서 생기나 | 카드 표기 |
| --- | --- | --- |
| **매장 등록** | `MCH-004` 사장이 콘솔에서 입력 | `8/12 · 매장 등록` |
| **후기 코멘트** | `EVD-005` 방문 후 입력 · 불일치 신고 | `8/20 · 후기 코멘트` |
| **운영자 검증** | `DAT-010` 재확인 큐 처리 | `7/28 · 운영자 검증` |
| **자동 수집** | `DAT-006` 색인 파이프라인 | `5/03 · 자동 수집` |

표기 형식은 `M/D · 주체` 로 고정한다. **픽스처는 네 값을 골고루 배치해 한 화면에서 4종이 모두 보이게 한다.**

| 확정 표기 | 쓰지 않는다 | 이유 |
| --- | --- | --- |
| **후기 코멘트** | 이용자 확인 · 리뷰 · 별점 · 평점 | '이용자 확인'은 어색하다. '리뷰·별점·3축'은 **v0.2로 연기한 리뷰 재가공**을 연상시킨다 |

## 3. 카피 규약 <!-- T3 -->

### 3.1 선정 이유 1줄 — 문장 틀 고정

```
<속성 나열> — 조건 N개 중 M개 충족
```

예: `1인석 6석 · 21시까지 영업 — 조건 3개 중 3개 충족`

**판정어를 넣을 자리가 없게 만든 틀이다.** '좋습니다' '추천합니다' 같은 단정을 쓰지 않는다는 규칙(SRS §6.3-4 · US-3 AC2 `판정형 문구 0건`)을 문장 구조로 강제한다. 속성이 없으면 문장이 만들어지지 않으므로 '근거 없는 후보는 카드가 될 수 없다'(§6.3-2)도 함께 지켜진다.

**미충족 개수를 숨기지 않는다.** `3개 중 2개 충족`을 그대로 쓴다 — 감추면 방문 후 불일치(현행 35%)로 돌아온다.

### 3.2 상태 화면 문구 — 확정 전문

에이전트가 창작하지 않는다. 아래를 그대로 쓴다.

| 상태 | 제목 | 본문 | 다음 행동 |
| --- | --- | --- | --- |
| **S6** 결과 0건 | 조건에 맞는 곳을 못 찾았습니다 | 반경 3km까지 넓혀 찾았습니다. | `조건 줄이기` `반경 더 넓히기` |
| **S7** 폴백 | 이 표현은 아직 이해하지 못했습니다 | *`<해석 못 한 표현>`* — 아래에서 직접 골라 주세요 | 구조화 필터 5종 + `이 조건으로 다시 찾기` |
| **S8** 오류 | 잠시 불러오지 못했습니다 | 잠시 뒤 다시 시도해 주세요. | `다시 시도` |

**쓰지 않는 표현** — `오류가 발생했습니다`(책임 모호) · `잘못된 입력입니다`(사용자 탓) · `검색 결과가 없습니다`(다음 행동 없음).

### 3.3 고지 배너 문구 — 확정 전문

## 6. 픽스처 데이터 <!-- T6 -->

### 6.1 상권과 질의

- **상권** — 서울 강남역 반경 1km. C3(마케터 점심)·C2(대학원생)·C4(프리랜서)가 겹치는 밀집 상권이라 픽스처가 현실적으로 읽힌다.
- **기본 질의** — `혼자 조용히 밥 먹을 곳, 2만원 이하`. C2(예산)와 C4(1인석) 조건이 한 문장에 걸려 있다.
- **매장명·메뉴·가격은 전부 합성이다** (MCK-001 보안 제약). 실재 매장을 쓰지 않는다.

### 6.2 후보 3종

| 순위 | 매장명 | 인당가 | 대표 | 상황 |
| --- | --- | --- | --- | --- |
| 1 | 무쇠솥 한상 | 1.1~1.4만 | 국밥 | 1인석 · 늦은 영업 |
| 2 | 온기식당 | 1.5~1.8만 | 백반 | 1인석 · 조용 |
| 3 | 느린한끼 | 1.6~1.9만 | 파스타 | 콘센트 · 체류 자유 |

### 6.3 확인 이력은 속성 단위다

US-3 AC2가 **"어떤 속성이 90일 이상 갱신되지 않았고, 그 속성이 카드에 노출되면"** 이라고 못 박고 있으므로, 확인 일자·주체는 카드가 아니라 **속성마다** 붙는다. 카드 슬롯 ⑤는 속성별로 1~2줄이 된다.

덕분에 카드 3장으로 **확인 주체 4종이 한 화면에 모두 보인다.**

| 상태 | 배치 |
| --- | --- |
| S3 정상 | 1번 `1인석/매장 등록` + `영업시간/운영자 검증` · 2번 `1인석/후기 코멘트` · 3번 `좌석/자동 수집` |
| S4 | 1번 가격이 `null` → **'가격 확인 필요'**, 가격 확인일 5/03 `stale` · 3번 좌석 확인일 4/18 `stale` |
| S5 | 1·2번만. 비교표가 2열로 줄어든다 |
