## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 조건이 자동 승계된다
- Given: 이용자가 대상 하나를 선택하고
- When: 예약 화면으로 넘어가면
- Then: 인원·메뉴 구성·시간이 자동 승계된다. **재입력 필드 0개 · 승계 누락률 ≤ 0.5% (US-4 AC1)**

Scenario 2: 주문량 기준으로 금액이 산출된다
- Given: 메뉴 구성이 포함된 선택이 주어지고
- When: 금액 산출이 실행되면
- Then: 주문량 기준 금액이 계산된다. **금액 산출 오류율 ≤ 0.3% (US-4 AC2)**

Scenario 3 (실패 흐름): 승계에 실패하면 결제로 넘어가지 않는다
- Given: 필수 승계 항목이 누락된 상태에서
- When: `assertNoReentry()` 가 실패하면
- Then: 예약 초안을 만들지 않고 사유를 반환한다. 재입력을 요구하는 화면으로 넘기지 않는다.

Scenario 4 (실패 흐름): 4인 미만은 선결제 대상이 아니다
- Given: 3인 예약이 주어지고
- When: 선결제 적용을 판정하면
- Then: 선결제 대상에서 제외된다. 소규모에까지 선결제를 걸면 전환율이 깎인다(R4). **§6.3-8 위반 0건**

## ⚙️ Technical & Non-Functional Constraints
- 품질: **US-4 AC1** 재입력 필드 0개 · 승계 누락률 ≤ 0.5%. **AC2** 금액 산출 오류율 ≤ 0.3%.
- 설계 원칙: **선결제는 4인 이상 단체 제안만**(§6.3-8) — R4(선결제가 전환을 깎음)의 완화 장치다.
- 기술 제약: **C-TEC-002** 변경 작업이므로 Server Action으로 구현한다.
