## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 콘솔이 독립 레이아웃으로 렌더된다
- Given: 인증된 가맹 세션이 있고
- When: 콘솔에 진입하면
- Then: 검색 화면과 다른 전용 레이아웃이 렌더되고 설정 화면이 3개를 넘지 않는다. **설정 화면 ≤ 3개 (US-5 AC1)**

Scenario 2 (실패 흐름): 미인증 진입이 차단된다
- Given: 세션이 없는 상태에서
- When: `/(merchant)` 경로에 진입하면
- Then: 레이아웃 렌더 전에 차단되고 콘솔 데이터가 응답에 포함되지 않는다.

## ⚙️ Technical & Non-Functional Constraints
- 사용자 특성: **P5는 조작 숙련도가 낮다**(SRS §8) — 화면 수 상한이 곧 이탈률 방어다.
- 기술 제약: **C-TEC-004 · D-08** shadcn/ui 컴포넌트를 자체 구현하지 않는다.
- 계층 분리: 이 태스크는 유형 `UI` 다 — 기능 구현(BE)과 분리해 추적한다(원칙 P6).
