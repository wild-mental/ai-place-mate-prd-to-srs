## ✅ Task Breakdown (실행 계획)
- [ ] 예약 확인 화면 — 승계된 인원·메뉴 구성·시간을 **읽기 전용**으로 표시
- [ ] **재입력 필드 0개** — 사용자가 다시 채워야 하는 칸이 없어야 한다 (US-4 AC1)
- [ ] 금액 표시 — 주문량 기준 산출 내역을 투명하게
- [ ] 선결제 안내 — **4인 이상 단체에만 적용**됨을 명확히. 왜 선결제인지 한 줄 설명
- [ ] 취소·환불 정책 표시 — 2시간 전 취소 시 전액 환불
- [ ] 결제 실패 상태 — 재시도 경로 제공
- [ ] 핸드오프 — `RSV-003` 구현 규격

## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 승계된 조건이 그대로 보인다
- Given: 제안을 선택한 상태에서
- When: 예약 화면으로 넘어가면
- Then: 인원·메뉴·시간이 읽기 전용으로 표시되고 입력할 칸이 없다. **재입력 필드 0개 (US-4 AC1)**

Scenario 2: 취소·환불 정책이 결제 전에 보인다
- Given: 결제 화면에서
- When: 선결제 안내를 보면
- Then: 2시간 전 취소 시 전액 환불이 명시된다. 결제 후에 알게 되면 신뢰가 깨진다.

Scenario 3 (실패 흐름): 결제 실패 시 되돌아갈 길이 있다
- Given: PG 승인이 거절된 상태에서
- When: 화면이 렌더되면
- Then: 사유와 재시도 경로가 제시된다. 예약은 미확정 상태로 유지된다.

## ⚙️ Technical & Non-Functional Constraints
- 품질: **US-4 AC1** 재입력 필드 0개 · 승계 누락률 ≤ 0.5%.
- 설계 원칙: **선결제는 4인 이상 단체만**(§6.3-8) — 소규모까지 걸면 전환율이 깎인다(R4).
- 신뢰: 취소·환불 정책을 **결제 전에** 보여 준다. 경쟁 서비스가 '0원 예약'을 내세운 시장이다.
