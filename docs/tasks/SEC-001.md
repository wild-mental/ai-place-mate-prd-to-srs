## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 30일 경과 데이터가 파기된다
- Given: 세션 종료 후 31일이 지난 참석자 출발지 데이터가 있고
- When: 파기 Cron이 실행되면
- Then: 해당 레코드가 물리 삭제되고 이후 조회되지 않는다. 29일 건은 남아 있어야 한다. **경계 오판 0건 (REQ-NF-010)**

Scenario 2 (실패 흐름): 외부에서 파기를 실행할 수 없다
- Given: `CRON_SECRET` 없이
- When: 파기 엔드포인트를 호출하면
- Then: 인증 거부로 응답하고 **파기 로직이 실행되지 않는다**. 임의 실행은 데이터 손실 사고다. **무단 실행 0건 (REQ-TEC-013)**

Scenario 3 (실패 흐름): Cron 실행 실패가 드러난다
- Given: 파기 Cron이 중단된 상태에서
- When: 마지막 성공 시각이 24시간을 넘으면
- Then: 알림이 발송된다. 파기가 조용히 멈추면 개인정보가 계속 남는다. **무증상 중단 0건 (R-T3)**

## ⚙️ Technical & Non-Functional Constraints
- 보안: **REQ-NF-010** 참석자 출발지는 세션 종료 후 30일 내 파기 · 목적 외 사용 금지. 개인 제약 정보는 **본인 단말에만** 저장한다.
- 기술 제약: **D-05 · REQ-TEC-013** Vercel Cron → Route Handler. 외부 호출 거부.
- 실행 순서: 집계(03:00) 이후 파기(05:00) — 파기 전 지표 집계가 끝나 있어야 한다.
