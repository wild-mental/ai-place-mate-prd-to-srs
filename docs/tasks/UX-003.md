## ✅ Task Breakdown (실행 계획)
- [ ] 조건 입력 화면 — 자연어 1줄 입력과 구조화 조건 입력을 한 화면에서
- [ ] **필수 입력 필드 0개** — 아무것도 입력하지 않아도 검색이 가능해야 한다 (US-2 AC3)
- [ ] 입력 단계 1회 이하 — 조건을 여러 화면에 나눠 받지 않는다
- [ ] **로딩 스켈레톤** — 500ms 내 렌더되는 형태. 결과 카드의 골격을 미리 보여 준다
- [ ] 모바일 초기 렌더 가이드 — 이미지·폰트 정책, 첫 화면에 필요한 자산 최소화 (REQ-NF-004)
- [ ] 진입 경로별 차이 정의 — 네이버 탭 임베드와 독립 웹의 헤더 처리
- [ ] 핸드오프 — `RNK-003` 이 그대로 구현할 수 있는 규격으로

## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 필수 입력 없이 검색이 가능하다
- Given: 조건 입력 화면이 노출된 상태에서
- When: 아무 조건도 입력하지 않고 검색하면
- Then: 결과가 반환된다. 필수 입력을 요구하면 C3가 이탈한다. **필수 입력 필드 0개 · 입력 단계 ≤ 1회 (US-2 AC3)**

Scenario 2 (실패 흐름): 대기 중 빈 화면이 없다
- Given: LLM 폴백으로 응답이 지연되는 상태에서
- When: 결과를 기다리면
- Then: 500ms 내 스켈레톤이 렌더된다. 흰 화면을 보여 주지 않는다. **스켈레톤 ≤ 500ms (REQ-NF-001b)**

## ⚙️ Technical & Non-Functional Constraints
- 성능: **REQ-NF-004** LCP ≤ 2.5s · **REQ-NF-001b** 스켈레톤 ≤ 500ms.
- 사용자 특성: **C3는 시간 제약이 강하다**(SRS §8) — 입력 부담이 곧 이탈이다.
- 기술 제약: **C-TEC-004 · D-08** shadcn/ui 인벤토리 안에서 구성한다.
