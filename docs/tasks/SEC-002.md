## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 조건 문장만 프롬프트에 담긴다
- Given: 사용자 세션과 위치 정보가 있는 요청에서
- When: LLM 파싱이 호출되면
- Then: 프롬프트에는 조건 문장만 포함되고 사용자 ID·좌표·연락처가 들어가지 않는다. **개인정보 포함 프롬프트 0건 (REQ-NF-010)**

Scenario 2 (실패 흐름): 개인정보가 섞이면 호출이 중단된다
- Given: 프롬프트 조립 중 금지 패턴이 검출되고
- When: 가드가 발동하면
- Then: **AI 호출을 하지 않고** 결정론 폴백으로 전환한다. 유출 후 되돌릴 방법이 없기 때문이다.

Scenario 3 (실패 흐름): 정적 검사가 위험한 코드를 막는다
- Given: 사용자 객체를 프롬프트에 직접 전달하는 코드가 추가되고
- When: 빌드를 실행하면
- Then: `verify-constraints` 가 이를 지목하고 빌드가 실패한다.

## ⚙️ Technical & Non-Functional Constraints
- 보안: **REQ-NF-010** 개인 제약 정보는 본인 단말에만. 프롬프트는 외부 전송이므로 **가장 엄격한 기준**을 적용한다.
- 기술 제약: **REQ-TEC-008** 모든 AI 호출이 `lib/ai.ts` 를 경유하므로 가드를 한 곳에만 두면 된다.
- 되돌림: 유출은 되돌릴 수 없다 — 검출 시 호출을 **중단**하고 폴백한다. 경고 후 진행하지 않는다.
