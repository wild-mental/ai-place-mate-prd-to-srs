## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 커넥션이 풀러를 경유한다
- Given: `DATABASE_URL` 이 Supavisor 트랜잭션 모드로 설정된 상태에서
- When: 애플리케이션이 DB에 접근하면
- Then: 포트 6543을 통해 연결되고 `pgbouncer=true` 파라미터가 적용된다. 직결(:5432)은 마이그레이션 전용이어야 한다. **런타임 직결 사용 0건**

Scenario 2: 로컬과 운영의 스키마가 일치한다
- Given: `supabase start` 로 로컬 환경이 기동된 상태에서
- When: 마이그레이션을 적용하고 드리프트를 검사하면
- Then: 로컬과 운영의 스키마 차이가 0이어야 한다. **드리프트 0건 (REQ-TEC-006)**

Scenario 3 (실패 흐름): 커넥션 환경 변수가 하나라도 없으면 빌드가 실패한다
- Given: `DIRECT_URL` 이 등록되지 않은 상태에서
- When: 빌드를 실행하면
- Then: `verify-constraints` 가 누락을 지목하고 빌드가 실패한다. 마이그레이션이 불가능한 상태로 배포되어서는 안 된다. **REQ-TEC-005 위반 배포 0건**

Scenario 4 (실패 흐름): 마이그레이션이 자동 적용되지 않는다
- Given: 스키마 변경이 포함된 커밋이 푸시된 상태에서
- When: Vercel 빌드가 실행되면
- Then: 빌드는 성공하되 **스키마 변경이 자동 적용되지 않는다.** 적용은 별도 승인 단계에서만 일어난다. **빌드 중 migrate deploy 실행 0회**

## ⚙️ Technical & Non-Functional Constraints
- 기술 제약: **C-TEC-003** Prisma + Supabase. **REQ-TEC-004** DB 접근은 `src/lib/db.ts` 싱글턴만 허용. **REQ-TEC-005** `DATABASE_URL`(:6543) / `DIRECT_URL`(:5432) 분리 필수.
- 처리량: **REQ-NF-003** Phase 1 300 RPS. 풀 사용률 80% 초과 시 알림(`REL-001`)이 뜨며, 3,000 RPS는 컴퓨트 상향이 전제다.
- 안정성: 마이그레이션을 빌드에 넣지 않는다 — 롤백이 어려운 스키마 변경의 자동 적용을 막기 위함 (SRS §14.4).
