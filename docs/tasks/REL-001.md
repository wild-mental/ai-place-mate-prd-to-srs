## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 경로별 p95가 분리 관측된다
- Given: `parse_path` 태깅이 적재되는 상태에서
- When: 관측 대시보드를 보면
- Then: 결정론 경로와 LLM 경로의 p95가 각각 표시된다. 합산 값만 보면 REQ-NF-001a 달성 여부를 알 수 없다.

Scenario 2 (실패 흐름): Cron이 멈추면 24시간 안에 드러난다
- Given: 어느 Cron의 마지막 성공이 25시간 전인 상태에서
- When: 감시가 실행되면
- Then: PagerDuty 알림이 발송된다. 신선도·마감·집계·파기가 조용히 멈추는 것이 이 프로젝트의 대표 실패 모드다. **무증상 중단 0건 (R-T3)**

Scenario 3 (실패 흐름): 커넥션 풀 고갈 전에 경고한다
- Given: Supavisor 풀 사용률이 85%인 상태에서
- When: 감시가 실행되면
- Then: 알림이 발송된다. 고갈되면 5xx가 급증한다(R-T2). **임계 80%**

## ⚙️ Technical & Non-Functional Constraints
- 성능: **REQ-NF-001a/001b** 경로별 임계. **REQ-NF-009** RTO ≤ 30분 — 롤백 절차가 이 목표의 수단이다.
- 조직: **전담 SRE가 없다**(SRS §2) — 관측·알림은 풀스택 리드가 겸하므로 자동 알림이 유일한 감지 수단이다.
- 한계: **LIM-T05** 플랫폼 장애는 자체 복구가 불가능하다. 상태 페이지 구독과 사용자 공지가 대응의 전부다.
