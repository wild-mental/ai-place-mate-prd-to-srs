## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 제안이 적합도 순으로 정렬된다
- Given: 여러 제안이 수집된 상태에서
- When: 정리해 보여 주면
- Then: 가격이 아니라 **조건 적합도를 1순위**로 정렬하고 비교 축과 근거를 함께 표시한다. **근거 표기율 100% · 가격 협상 기능 0건 (US-6 AC3)**

Scenario 2 (실패 흐름): 근거 없는 제안 문구가 거부된다
- Given: 등록 속성으로 뒷받침되지 않는 headline이 주어지고
- When: 제출하면
- Then: 400을 반환하고 저장하지 않는다. **근거 없는 제안 문구 0건**

Scenario 3 (실패 흐름): 마감 후 제출이 거부된다
- Given: `expiresAt` 이 지난 대화방에
- When: 제안을 제출하면
- Then: 거부한다. 마감 판정은 서버 시각 기준이므로 클라이언트 시계 조작으로 우회할 수 없어야 한다.

Scenario 4 (실패 흐름): 불이행 신고가 소환 가중치를 낮춘다
- Given: 선택된 제안이 현장에서 이행되지 않아 신고된 상태에서
- When: 신고가 처리되면
- Then: 불이행이 기록되고 해당 매장의 소환 가중치가 하향된다. **제안 이행률 ≥ 95% · 신고 처리 ≤ 48h (US-6 AC5)**

## ⚙️ Technical & Non-Functional Constraints
- 설계 원칙: **가격 협상 기능 0건**(§6.3-7) — `Proposal` 에 가격 필드가 없으므로 실수로 정렬 키에 넣을 수 없다.
- 품질: **보조 9** 제안 이행률 ≥ 95%. **§6.3-10** 불이행 시 소환 가중치 하향.
- 성능: **US-6 AC2** 첫 제안 p50 ≤ 60s · 180초 내 제안 1건 이상 도착률 85%.
