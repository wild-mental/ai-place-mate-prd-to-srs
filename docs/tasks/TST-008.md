## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 스키마와 정책이 규약을 만족한다
- Given: 마이그레이션이 적용된 상태에서
- When: 검사를 실행하면
- Then: RLS 전 테이블 활성화·금지 컬럼 0개·이벤트 계약 일치가 확인된다.

Scenario 2 (실패 흐름): RLS가 빠진 테이블을 잡아낸다
- Given: RLS가 비활성화된 테이블이 추가되고
- When: 검사를 실행하면
- Then: 해당 테이블명을 지목하고 빌드가 실패한다. **RLS 누락 테이블 0개 (REQ-NF-012)**

Scenario 3 (실패 흐름): 금지 컬럼이 추가되면 차단된다
- Given: `Payment` 에 카드 번호 컬럼을 추가하고
- When: 검사를 실행하면
- Then: 빌드가 실패한다. 카드 정보 비보관은 타협 대상이 아니다. **카드 정보 컬럼 0개 (REQ-NF-011)**

Scenario 4 (실패 흐름): 이벤트 계약 불일치를 잡아낸다
- Given: 이벤트에 필수 속성이 빠진 채 적재되고
- When: 계약 테스트를 실행하면
- Then: 불일치가 보고된다. 지표 집계가 조용히 틀어지는 것을 막는다.
