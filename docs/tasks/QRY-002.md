## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 구조화 출력이 스키마 검증을 통과한다
- Given: 결정론 파서가 해석하지 못한 질의가 주어지고
- When: Gemini 폴백이 호출되면
- Then: `Output.object` 로 `ConditionSet` 형태가 반환되고 스키마 검증을 통과한다. **LLM 경로 p95 ≤ 2,500ms (REQ-NF-001b)**

Scenario 2: 모델을 코드 변경 없이 교체할 수 있다
- Given: `AI_MODEL_PARSE` 환경 변수가 설정된 상태에서
- When: 값을 다른 모델 ID로 바꾸고 재배포하면
- Then: **코드가 한 줄도 바뀌지 않고** 동작하며 파싱 결과 스키마가 동일하게 유지된다. **코드 변경 0줄 (REQ-TEC-009)**

Scenario 3 (실패 흐름): 타임아웃 시 폴백으로 열화한다
- Given: Gemini 응답이 2,000ms를 초과하는 상태에서
- When: `abortSignal` 이 발동하면
- Then: 호출을 중단하고 구조화 필터 폴백으로 전환한다. 빈 화면이 나오지 않아야 한다. **빈 화면 노출 0건 (§6.3-6)**

Scenario 4 (실패 흐름): 스키마 검증 실패 응답을 사용하지 않는다
- Given: LLM이 스키마에 맞지 않는 응답을 반환한 상태에서
- When: 검증이 실패하면
- Then: 해당 응답을 **폐기**하고 결정론 폴백으로 전환한다. 검증되지 않은 값이 하류로 흘러가면 안 된다. **미검증 응답 사용 0건 (REQ-TEC-010)**

## ⚙️ Technical & Non-Functional Constraints
- 성능: **REQ-NF-001b** LLM 경로 p95 ≤ 2,500ms. 타임아웃 2,000ms + 폴백 여유로 구성한다.
- 비용: **REQ-NF-013** 세션당 ≤ 12원. 출력 토큰 상한 · 파싱 캐시 · 결정론 흡수 3중 방어. 일간 18원 초과 시 알림.
- 보안: **REQ-NF-010** 프롬프트에 개인 식별 정보를 넣지 않는다 — 조건 문장만 전달하고 사용자 ID·좌표·연락처를 포함하지 않는다 (`SEC-002` 가 검증).
- 기술 제약: **C-TEC-005** 자체 AI 서버 없이 Vercel AI SDK로 외부 API를 호출한다. **C-TEC-006** Gemini 기본 · SDK 표준 인터페이스 준수. **REQ-TEC-008** 모든 호출은 `src/lib/ai.ts` 경유.
- 외부 의존: **LIM-T06** AI 응답 지연은 우리 코드로 줄일 수 없다. 타임아웃·폴백·캐시가 유일한 방어다.
