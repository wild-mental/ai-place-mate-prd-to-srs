## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: MFA를 통과해야 콘솔에 접근한다
- Given: 가맹 계정이 등록된 상태에서
- When: 비밀번호만으로 로그인을 시도하면
- Then: 2단계 인증을 요구하고, 완료 전까지 콘솔 데이터가 반환되지 않는다. **MFA 미적용 접근 0건 (REQ-NF-012)**

Scenario 2 (실패 흐름): 다른 매장 데이터에 접근할 수 없다
- Given: 가맹 A로 인증된 세션이 있고
- When: 가맹 B의 프로필·제안을 조회하면
- Then: RLS가 거부한다. 애플리케이션 코드가 아니라 **DB 정책이 최종 방어선**이다. **비인가 반환 0행**

## ⚙️ Technical & Non-Functional Constraints
- 보안: **REQ-NF-012** 가맹 콘솔 2FA · 내부 조회 전량 감사 로그. Supabase Auth MFA를 사용한다.
- 기술 제약: **C-TEC-003** 인증 정책이 Supabase 기능 범위에 제한된다(SRS §15-8).
- 의존: `DAT-008` 의 RLS 정책과 짝을 이룬다 — 인증만 있고 정책이 없으면 격리가 성립하지 않는다.
