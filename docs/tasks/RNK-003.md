## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 결정론 경로가 1초 안에 렌더된다
- Given: 결정론 파서가 조건을 해석한 상태에서
- When: 결과 페이지가 요청되면
- Then: Top-3가 근거와 함께 스트리밍 렌더된다. **p95 ≤ 1,000ms (REQ-NF-001a)**

Scenario 2: LLM 경로에서도 즉시 스켈레톤이 뜬다
- Given: LLM 폴백이 진행 중인 상태에서
- When: 결과 페이지가 요청되면
- Then: 500ms 내 스켈레톤이 렌더되고 조건 확정 후 결과가 채워진다. **스켈레톤 ≤ 500ms · 전체 p95 ≤ 2,500ms (REQ-NF-001b)**

Scenario 3 (실패 흐름): 파싱 실패 시 구조화 필터 화면으로 전환된다
- Given: 파싱이 최종 실패한 상태에서
- When: 결과 페이지가 렌더되면
- Then: 빈 화면 대신 구조화 필터 UI가 렌더되고 해석하지 못한 표현이 표기된다. **빈 화면 노출 0건 (US-1 AC5)**

Scenario 4 (실패 흐름): 결과가 0건이어도 화면이 비지 않는다
- Given: 폴백까지 거쳐도 후보가 0건인 상태에서
- When: 페이지가 렌더되면
- Then: 사유와 다음 행동(조건 완화·반경 확대)을 담은 상태 화면이 렌더된다.

## ⚙️ Technical & Non-Functional Constraints
- 성능: **REQ-NF-001a** ≤ 1,000ms · **REQ-NF-001b** ≤ 2,500ms · **REQ-NF-004** LCP ≤ 2.5s (4G).
- 기술 제약: **C-TEC-001 · 002** RSC에서 DB를 직접 조회한다. 내부 REST를 만들어 자기 자신을 `fetch` 하지 않는다(D-02).
- 계층 분리: 이 태스크는 유형 `UI` 다 — **기능 구현(BE)과 분리**해 담당·리뷰 관점을 나눈다(원칙 P6).
- 설계 원칙: **빈 화면 금지**(§6.3-6)를 화면 수준에서 최종 보증하는 지점이다.
