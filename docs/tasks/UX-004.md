## ✅ Task Breakdown (실행 계획)
- [ ] 구조화 필터 폴백 화면 — 자연어 파싱 실패 시 전환되는 필터 UI
- [ ] **해석하지 못한 표현을 그대로 표기** — 무엇을 못 알아들었는지 사용자가 알 수 있게
- [ ] 빈 상태 정의 — 결과 0건 · 후보 부족(1~2건) · 커버리지 부족 각각의 화면
- [ ] 오류 상태 정의 — 일시 오류 · 외부 시스템 실패. 사용자가 할 수 있는 다음 행동을 함께 제시
- [ ] 제안 0건 복귀 화면 규격 — `AGR-006` 이 사용
- [ ] 상태별 문구 톤 — 시스템 탓을 사용자에게 돌리지 않는다
- [ ] 핸드오프 — `RNK-003` · `AGR-006` 이 구현할 규격

## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1 (실패 흐름): 파싱 실패가 필터 화면으로 이어진다
- Given: 자연어 조건 해석이 실패한 상태에서
- When: 화면이 전환되면
- Then: 구조화 필터 UI가 렌더되고 **해석하지 못한 표현이 그대로 표기**된다. **빈 화면 노출 0건 (US-1 AC5)**

Scenario 2 (실패 흐름): 결과 0건에도 다음 행동이 있다
- Given: 폴백까지 거쳐도 후보가 0건인 상태에서
- When: 빈 상태가 렌더되면
- Then: 사유와 함께 조건 완화·반경 확대 같은 다음 행동이 제시된다. 막다른 화면을 만들지 않는다.

## ⚙️ Technical & Non-Functional Constraints
- 설계 원칙: **빈 화면 금지**(§6.3-6) — 이 태스크가 그 규칙의 화면 근거를 만든다.
- 품질: **REQ-NF-007** 파싱 실패율 ≤ 1.5% · 빈 결과 반환률 ≤ 2%. 낮아도 0은 아니므로 화면이 반드시 필요하다.
- 톤: 실패를 사용자 탓으로 돌리는 문구를 쓰지 않는다.
