## ✅ Task Breakdown (실행 계획)
- [ ] 조건 카테고리 사전 구축 — 가격·메뉴·상황 속성(1인석·소음·체류)·단체 조건을 항목별로 등재
- [ ] 결정론 파서 구현 — 사전 매칭 + 규칙 기반. 반환 타입은 `CTR-001` 의 `ConditionSet`
- [ ] 정규화 규칙 — 어순 차이·조사 제거·동의어 매핑으로 같은 질의를 같은 키로 수렴
- [ ] 파싱 캐시 구현 — `정규화 질의 → ConditionSet`. `use cache` 계층(`DAT-006`) 위에 얹는다
- [ ] 흡수율 계측 — 캐시 히트 / 결정론 성공 / 미스를 구분해 `parse_path` 로 적재
- [ ] 미매칭 질의 로그 수집 — 사전 확장의 재료 (SRS §7.2)
- [ ] 성능 예산 확인 — 정규화·캐시 조회 ≤ 20ms, 결정론 파싱 ≤ 30ms
- [ ] 단위 테스트 — 사전 등재 표현 적중, 캐시 히트 시 재계산 없음, 예산 초과 감지

## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 사전에 있는 조건이 LLM 없이 해석된다
- Given: '인당 2만원 이하 평양냉면 혼자' 처럼 사전 등재 표현으로 구성된 질의가 주어지고
- When: 결정론 파서가 실행되면
- Then: LLM 호출 없이 `ConditionSet` 이 반환된다. **결정론 파싱 ≤ 30ms · 흡수율 ≥ 70% (REQ-FUNC-004)**

Scenario 2: 동일 질의가 캐시로 재사용된다
- Given: 이전에 LLM으로 해석된 질의가 캐시에 적재된 상태에서
- When: 어순만 다른 같은 의미의 질의가 들어오면
- Then: 정규화 후 캐시 히트로 즉시 반환되고 LLM을 재호출하지 않는다. **캐시 히트율 ≥ 60% · 동일 질의 LLM 재호출 0건 (REQ-NF-002b)**

Scenario 3 (실패 흐름): 사전에 없는 표현은 해석하지 않고 넘긴다
- Given: 사전에 없는 상황어가 포함된 질의가 주어지고
- When: 결정론 파서가 실행되면
- Then: **추측하지 않고** 미해석으로 표시해 LLM 폴백(`QRY-002`)으로 넘긴다. 잘못 해석한 조건을 만들어내면 안 된다. **오해석으로 인한 불일치 신고 기여 0건**

Scenario 4 (실패 흐름): 흡수율이 목표에 못 미치면 드러난다
- Given: `parse_path` 계측이 동작하는 상태에서
- When: 일간 분포를 집계하면
- Then: LLM 경로 비율이 40%를 넘으면 알림이 발송된다. 비용·지연이 동시에 악화되는 신호다. **LLM 호출 비율 일간 ≤ 40% (SRS §10.3)**

## ⚙️ Technical & Non-Functional Constraints
- 성능: **REQ-NF-001a** 결정론 경로 p95 ≤ 1,000ms. 이 태스크의 예산은 정규화·캐시 20ms + 파싱 30ms.
- 비용: **REQ-NF-013** 세션당 추론 비용 ≤ 12원. 결정론 흡수와 파싱 캐시가 1차 방어선이다.
- 기술 제약: **D-03 · REQ-TEC-015** 파싱 캐시도 외부 캐시 서버 없이 `use cache` 로 구현한다.
- 설계 원칙: **판정하지 않는다**(§6.3-4) — 사전에 없는 표현을 억지로 매핑하지 않고 폴백에 넘긴다.
