## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: Git Push만으로 배포된다
- Given: Vercel 프로젝트가 저장소에 연결된 상태에서
- When: main 브랜치에 커밋을 푸시하면
- Then: 외부 CI 설정 없이 프로덕션 배포가 자동 실행된다. 저장소에 CI 워크플로 파일이 존재하지 않아야 한다. **워크플로 파일 0개 (REQ-TEC-011)**

Scenario 2: Cron 5종이 스케줄대로 호출된다
- Given: `vercel.ts` 의 `crons` 가 배포된 상태에서
- When: 각 스케줄 시각이 지나면
- Then: 해당 Route Handler가 호출되고 실행 로그가 남는다. 경로는 SRS §6.1의 Cron 표와 정확히 일치해야 한다.

Scenario 3 (실패 흐름): 필수 환경 변수가 없으면 배포가 차단된다
- Given: `GOOGLE_GENERATIVE_AI_API_KEY` 가 등록되지 않은 상태에서
- When: 빌드를 실행하면
- Then: `check-env.mjs` 가 누락 변수명을 출력하고 **빌드가 실패**한다. 변수 없이 배포된 산출물이 존재해서는 안 된다. **누락 상태 배포 0건**

## ⚙️ Technical & Non-Functional Constraints
- 기술 제약: **C-TEC-001** 단일 Next.js 앱. **C-TEC-007** 배포·인프라를 Vercel로 단일화하고 외부 CI를 두지 않는다. **REQ-TEC-013** Cron 엔드포인트는 `CRON_SECRET` 으로 인증한다.
- 런타임: 기본 **Node.js 런타임**을 사용한다. Prisma와 Node API 전체가 필요하므로 Edge 런타임을 쓰지 않는다 (SRS §3.1).
- 보안: `SUPABASE_SERVICE_ROLE_KEY` 는 **클라이언트에 노출 금지**. `NEXT_PUBLIC_` 접두어를 붙이지 않는다 (SRS §6.5).
- 되돌림 비용: 낮음 — 다만 디렉터리 구조 변경은 이후 전 태스크의 경로에 영향을 주므로 S-1에서 확정한다.
