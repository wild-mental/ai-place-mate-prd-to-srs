## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 세 경로가 각각 태깅된다
- Given: 캐시 히트 · 결정론 성공 · LLM 폴백 세 상황이 각각 주어지고
- When: `submitQuery` 가 실행되면
- Then: `parse_path` 가 `cache` / `deterministic` / `llm` 으로 정확히 구분되어 적재된다. 이 값으로 경로별 p95가 분리 측정된다.

Scenario 2: 계측이 응답을 지연시키지 않는다
- Given: 계측 적재가 `after()` 로 구현된 상태에서
- When: 액션이 실행되면
- Then: 이벤트 적재는 응답 이후에 수행되고 사용자 응답 시간에 포함되지 않는다. **계측으로 인한 지연 0ms (ADR-T07)**

Scenario 3 (실패 흐름): 파싱 실패 시 구조화 필터로 전환한다
- Given: 사전에 없는 표현이고 LLM도 스키마 검증에 실패한 상태에서
- When: 액션이 완료되면
- Then: 빈 화면 대신 구조화 필터 UI 경로를 반환하고 **해석하지 못한 표현을 그대로 표기**한다. **파싱 실패율 ≤ 1.5% · 빈 화면 노출 0건 (US-1 AC5)**

Scenario 4 (실패 흐름): 인가되지 않은 호출이 거부된다
- Given: Server Action이 외부에서 직접 호출된 상태에서
- When: 인가 확인이 실패하면
- Then: `{ ok: false }` 로 거부하고 하류 로직을 실행하지 않는다. 스택이 노출되어서는 안 된다.

## ⚙️ Technical & Non-Functional Constraints
- 성능: **REQ-NF-001a** 결정론 경로 p95 ≤ 1,000ms / **REQ-NF-001b** LLM 경로 p95 ≤ 2,500ms — `parse_path` 로 분리 측정한다.
- 안정성: **REQ-NF-007** 최종 파싱 실패율 ≤ 1.5%, 실패 시 구조화 필터로 열화.
- 기술 제약: **C-TEC-002** Server Action은 POST 전용이며 GET 캐시가 없다(**LIM-T04**). 캐시가 필요한 읽기는 RSC로 둔다.
- 계측 필수: `top3_rendered` 와 `query_committed` 에 `parse_path` 를 반드시 포함한다 — 없으면 성능 요구사항을 판정할 수 없다.
