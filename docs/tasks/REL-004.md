## ✅ Task Breakdown (실행 계획)
- [ ] Supabase 프로젝트에서 **PITR 활성화** (플랜 요건 확인)
- [ ] 복구 지점 간격 확인 — RPO ≤ 5분 충족 여부
- [ ] 복구 절차 문서화 — 어떤 상황에서 누가 어떻게 복구하는지
- [ ] 복원 훈련 1회 — 스테이징에서 특정 시점 복구를 실제로 수행
- [ ] RTO 측정 — 훈련에서 실제 소요 시간을 기록 (목표 ≤ 30분)

## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: PITR이 활성화되어 있다
- Given: Supabase 프로젝트 설정에서
- When: 백업 정책을 확인하면
- Then: PITR이 켜져 있고 복구 지점 간격이 목표를 만족한다. **RPO ≤ 5분 (REQ-NF-009)**

Scenario 2 (실패 흐름): 복원 훈련으로 RTO를 실측한다
- Given: 스테이징 환경에서
- When: 특정 시점 복구를 수행하면
- Then: 완료까지 소요 시간이 기록된다. 목표를 넘으면 절차를 단축해야 한다. **RTO ≤ 30분**

## ⚙️ Technical & Non-Functional Constraints
- 신뢰성: **REQ-NF-009** RTO ≤ 30분 · RPO ≤ 5분.
- 기술 제약: **C-TEC-003** Supabase 기능 범위에서 해결한다. 자체 백업 인프라를 만들지 않는다.
- 비용: PITR은 플랜에 따라 비용이 발생한다 — 예산 항목으로 인지해야 한다.
