## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 토큰이 Tailwind 테마로 등록 가능하다
- Given: 토큰 정의가 완료된 상태에서
- When: 개발이 테마로 옮기면
- Then: 추가 해석 없이 그대로 등록된다. 값이 모호해 재문의가 발생하지 않아야 한다.

Scenario 2 (실패 흐름): 인벤토리에 없는 컴포넌트 요구가 걸러진다
- Given: 화면 설계에서 새 컴포넌트가 필요해지고
- When: 인벤토리를 확인하면
- Then: shadcn/ui에 대응물이 있으면 **그것을 쓰도록 결정**된다. 자체 제작은 대응물이 없을 때만 승인된다. **중복 구현 0건 (D-08 · REQ-TEC-007)**

## ⚙️ Technical & Non-Functional Constraints
- 기술 제약: **C-TEC-004** Tailwind + shadcn/ui. **D-08** 존재하는 컴포넌트를 다시 만들지 않는다.
- 성능: **REQ-NF-004** LCP ≤ 2.5s — 웹폰트 수·이미지 정책이 이 목표에 직결된다.
- 범위: 이 태스크는 **디자인 산출물**이다. 코드 등록은 `INF-002`(Part A)가 한다 — 두 관점을 분리한다.
