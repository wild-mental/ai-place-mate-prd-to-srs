## ✅ Task Breakdown (실행 계획)

- [ ] 1단계 — 해당 `canonicalKey` 존재 시 매장 목록 반환 (업종 목록이 아니라 **매장** 목록)

- [ ] 단위 테스트 — 4단계 분기 전부, 유사 메뉴 3건 경계, 반경 확대 1회 제한

## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 메뉴명 하나로 매장이 반환된다
- Given: 이용자가 반경 1km 안에 있고 색인에 해당 메뉴가 있으면
- When: 검색창에 메뉴명만 입력하면
- Then: 업종 목록이 아니라 그 메뉴를 취급하는 매장이 반환된다. **정답 반환률 ≥ 92% · 첫 결과 p95 ≤ 1,000ms (US-2 AC1)**

Scenario 2 (실패 흐름): 색인에 없으면 유사 메뉴로 대체한다
- Given: 메뉴 색인에 해당 메뉴가 없고 유사 메뉴가 3건 이상 존재하면
- When: 검색이 실행되면
- Then: '찾는 메뉴가 없어 유사 메뉴로 대체했다'를 명시하고 반환한다. **빈 결과 반환률 ≤ 2% (US-2 AC2)**

Scenario 3 (실패 흐름): 반경 내 0건이면 자동 확대한다
- Given: 반경 1km 안에 해당 메뉴도 유사 메뉴도 없고
- When: 검색이 실행되면
- Then: 반경을 3km로 **1회** 자동 확대하고 확대 사실을 표기한다. 그래도 0건이면 인접 카테고리를 사유와 함께 반환한다. **결과 0건 종료 0회 · 반경 확대 표기율 100% (US-2 AC4)**

## ⚙️ Technical & Non-Functional Constraints
- 성능: **REQ-NF-001a** 첫 결과 p95 ≤ 1,000ms. 메뉴명 질의는 LLM이 불필요하므로 **항상 결정론 경로**여야 한다.
- 안정성: **REQ-NF-007** 빈 결과 반환률 ≤ 2%. 폴백 단계마다 대체 사실을 표기한다.
- 설계 원칙: **빈 화면 금지**(§6.3-6) — 어느 단계에서도 '결과 없음'으로 종료하지 않는다.
