## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 3~5곳이 소환되어 대화방이 만들어진다
- Given: 이용자가 카테고리와 지역을 말하고 적합 매장이 8곳 있으면
- When: 소환이 실행되면
- Then: 적합도 상위 3~5곳만 소환되어 하나의 대화방이 생성된다. **소환 수 3–5곳 · 대화방 생성 p95 ≤ 2,000ms (US-6 AC1)**

Scenario 2 (실패 흐름): 적합 매장이 0곳이면 대화방을 만들지 않는다
- Given: 수용 조건을 만족하는 매장이 0곳인 상태에서
- When: 소환이 실행되면
- Then: **즉시 미개시 응답**을 반환하고 대화방을 생성하지 않는다. 참여 매장 없는 빈 대화방을 만들면 '참여 매장이 없는 서비스'로 읽힌다.

Scenario 3 (실패 흐름): 조건이 1개면 소환하지 않는다
- Given: 조건이 1개만 주어진 상태에서
- When: 소환을 시도하면
- Then: 입력 검증에서 거부한다. 조건이 부족하면 부적합 소환이 늘어난다. **조건 2개 이상 필수 (SRS §6.1)**

## ⚙️ Technical & Non-Functional Constraints
- 성능: **US-6 AC1** 대화방 생성 p95 ≤ 2,000ms.
- 설계 원칙: 마감은 **서버 `expiresAt` 기준**이며 클라이언트 타이머를 신뢰하지 않는다(ADR-T06).
- 품질: **보조 11** 가맹점 월 제안 참여율 60% — `Summon` 레코드가 이 지표의 분모다.
- 리스크: **R1** 매장의 제안 참여가 목표에 미달하면 이 기능 전체가 성립하지 않는다. 게이트 1의 가맹 LOI 30곳이 선행 확인 장치다.
