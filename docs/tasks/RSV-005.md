## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 2시간 전 취소가 전액 환불된다
- Given: 이용자가 예약 2시간 전까지 취소하고
- When: 취소가 접수되면
- Then: 선결제 금액을 전액 환불하고 매장에 즉시 알린다. **환불 처리 ≤ 24h · 환불 실패율 ≤ 0.5% (US-4 AC3)**

Scenario 2 (실패 흐름): 방문 확인이 없으면 노쇼로 기록된다
- Given: 예약 시각이 지나고 방문 확인이 없는 상태에서
- When: 노쇼 판정 Cron이 실행되면
- Then: 노쇼로 기록하고 선결제 금액을 매장에 정산한다. **선택 제안 노쇼율 ≤ 5% · 오판정률 ≤ 1% (US-4 AC4)**

Scenario 3 (실패 흐름): 매장 귀책은 노쇼가 아니다
- Given: 매장 측 수용 불가 사유가 기록된 상태에서
- When: 노쇼 판정이 실행되면
- Then: 노쇼로 기록하지 않고 이용자에게 환불한다. 매장이 문을 닫았는데 이용자를 노쇼로 기록하면 오판정률 1%를 지킬 수 없다.

Scenario 4 (실패 흐름): 노쇼율이 임계를 넘으면 제안이 중단된다
- Given: 주간 노쇼율이 8%를 넘은 상태에서
- When: 집계가 완료되면
- Then: 알림이 발송되고 에이전트 제안의 **신규 노출이 중단**된다. 가맹점은 노쇼 한 번으로 이탈한다. **임계 8% (SRS §10.3)**

## ⚙️ Technical & Non-Functional Constraints
- 품질: **US-4 AC3** 환불 ≤ 24h · 실패율 ≤ 0.5%. **AC4** 노쇼율 ≤ 5% · 오판정률 ≤ 1%.
- 기술 제약: **D-05 · REQ-TEC-013** 노쇼 판정은 Vercel Cron → Route Handler. 상시 스케줄러를 두지 않는다.
- 설계 원칙: **매장 귀책 분기를 노쇼 판정 앞에 둔다** — 오판정률 목표를 지키는 유일한 방법이다(SDD FC-05).
- 게이트: 노쇼율 8% 초과는 **게이트 2 미달** 신호이며 F7·F8을 v0.2로 연기하는 판단 근거가 된다.
