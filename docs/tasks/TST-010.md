## ✅ Task Breakdown (실행 계획)
- [ ] 부하 테스트 스크립트 작성 — 300 RPS 목표 (Phase 1 기준)
- [ ] **경로별 분리 측정** — `parse_path` 로 결정론 경로와 LLM 경로의 p95를 나눠 측정
- [ ] 시나리오 구성 — 결정론 70% / LLM 30% 비율로 실제 분포를 모사
- [ ] Supavisor 풀 사용률 동시 관측 — 80% 초과 여부 (R-T2)
- [ ] **LCP 측정** — 4G 조건에서 모바일 초기 렌더 (REQ-NF-004)
- [ ] 결과 리포트 — 목표 대비 실측, 병목 구간 지목 (성능 예산 §4.2.1의 어느 구간인지)
- [ ] 게이트 판정 자료 제출 — 게이트 2 통과 여부의 근거

## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 300 RPS에서 경로별 목표를 만족한다
- Given: Phase 1 규모 데이터가 적재된 상태에서
- When: 300 RPS 부하를 가하면
- Then: 결정론 경로와 LLM 경로의 p95가 각각 목표 안에 든다. **결정론 ≤ 1,000ms · LLM ≤ 2,500ms · 풀 사용률 ≤ 80% (REQ-NF-001a·001b·003)**

Scenario 2: 모바일 초기 렌더가 목표를 만족한다
- Given: 4G 회선 조건에서
- When: 첫 화면을 측정하면
- Then: LCP가 목표 안에 든다. **LCP ≤ 2.5s (REQ-NF-004)**

Scenario 3 (실패 흐름): 목표 미달 시 병목 구간을 지목한다
- Given: p95가 목표를 초과한 상태에서
- When: 리포트를 산출하면
- Then: 성능 예산(§4.2.1)의 어느 구간이 초과했는지 명시된다. '느리다'가 아니라 **어디가 느린지**를 알려야 한다.

## ⚙️ Technical & Non-Functional Constraints
- 성능: **REQ-NF-001a/001b · REQ-NF-003 · REQ-NF-004** 전부 이 태스크가 검증한다.
- 게이트: **SRS §10.4 게이트 2** 통과 조건이 '300 RPS 부하 테스트 통과'다. 이 태스크 없이는 게이트를 판정할 수 없다.
- 한계: 3,000 RPS(Phase 2)는 Supabase 컴퓨트 상향이 전제다(SRS §15-3). 이 테스트는 Phase 1 목표만 검증한다.
