## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 월 가용성이 합성으로 산출된다
- Given: 두 플랫폼의 가동 데이터가 수집된 상태에서
- When: 월간 집계가 실행되면
- Then: 각 플랫폼 가용성과 그 곱으로 계산한 합성 가용성이 산출된다. **목표 ≥ 99.5% · 월 다운타임 ≤ 3시간 39분 (REQ-NF-005)**

Scenario 2 (실패 흐름): 목표 미달이 판단 근거로 보고된다
- Given: 합성 가용성이 99.2%로 목표에 못 미친 상태에서
- When: 월간 리포트가 산출되면
- Then: 격차와 원인(어느 플랫폼의 다운타임인지)이 명시되고 §15.1의 결정 안건으로 올라간다. **감추지 않는다**.

Scenario 3 (실패 흐름): 자체 복구가 불가능함을 전제로 대응한다
- Given: 플랫폼 장애가 발생한 상태에서
- When: 대응을 실행하면
- Then: 상태 페이지 확인과 사용자 공지가 수행된다. **LIM-T05** 에 따라 자체 복구 수단은 없다.

## ⚙️ Technical & Non-Functional Constraints
- 신뢰성: **REQ-NF-005** 월 가용성 ≥ 99.5%. 두 플랫폼 가용성이 **곱으로** 작용하므로 각 구성요소는 ≥ 99.9%를 전제로 한다.
- 한계: **LIM-T05** 플랫폼 장애는 자체 복구 불가. 이 태스크는 복구가 아니라 **측정과 판단 근거 제공**이 역할이다.
- 미해소: **SRS §15.1** — 99.5%를 계약상 보증하려면 멀티 클라우드가 필요하고 이는 C-TEC-007과 충돌한다. 실측이 이 결정의 입력이다.
