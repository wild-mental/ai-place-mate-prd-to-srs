## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 디자인 토큰이 Tailwind 테마로 동작한다
- Given: `UX-001` 의 토큰이 테마에 등록된 상태에서
- When: 컴포넌트에서 토큰 기반 유틸리티 클래스를 사용하면
- Then: 정의된 색·간격·타이포가 적용되고, 하드코딩된 색상값이 코드에 남아 있지 않다. **하드코딩 색상값 0건**

Scenario 2: 두 진입 경로가 모두 동작한다
- Given: 네이버 지도 탭과 독립 모바일 웹이 배포된 상태에서
- When: 각 경로로 진입하면
- Then: 동일한 앱이 렌더되고 진입 경로가 계측 이벤트의 `entry_point` 속성으로 구분된다.

Scenario 3 (실패 흐름): shadcn/ui에 있는 컴포넌트를 자체 구현하면 차단된다
- Given: 인벤토리에 등재된 컴포넌트가 있고
- When: 같은 역할의 컴포넌트를 직접 작성하면
- Then: ESLint가 오류를 내고 **빌드가 실패**한다. 중복 구현이 머지되지 않아야 한다. **중복 구현 0건 (D-08)**

## ⚙️ Technical & Non-Functional Constraints
- 기술 제약: **C-TEC-004** UI·스타일링은 Tailwind + shadcn/ui로 한정한다. **D-08** shadcn/ui에 존재하는 컴포넌트를 다시 만들지 않는다.
- 성능: **REQ-NF-004** 모바일 초기 렌더 LCP ≤ 2.5s (4G 기준). 클라이언트 번들을 최소화하고 Server Component를 우선한다.
- 유통 제약: **LIM-T05 · ADR-005** 네이버 지도 탭의 노출·정책 결정권이 당사에 없다. 독립 웹 경로를 항상 병행 유지한다.
