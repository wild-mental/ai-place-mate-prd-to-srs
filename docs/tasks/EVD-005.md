## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 신고가 재확인 큐로 연결된다
- Given: 방문이 완료된 상태에서
- When: 이용자가 '조건이 달랐다'를 신고하면
- Then: 해당 속성의 확인 상태가 '재확인 필요'로 즉시 전환되고 큐에 적재된다. **반영 지연 ≤ 60s (US-3 AC4)**

Scenario 2 (실패 흐름): 같은 속성을 반복 신고해도 큐가 폭주하지 않는다
- Given: 이미 `NEEDS_REVERIFY` 인 속성이 있고
- When: 다른 이용자가 같은 속성을 신고하면
- Then: 새 태스크를 중복 생성하지 않고 신고 횟수만 누적한다. 큐가 같은 항목으로 채워지면 안 된다.

## ⚙️ Technical & Non-Functional Constraints
- 품질: **보조 6** 방문 후 조건 불일치 신고율 ≤ 10%. 이 값이 높으면 근거 품질 문제이지 신고 기능 문제가 아니다.
- 성능: 전환은 60초 내. Server Action에서 동기 처리하고 계측만 `after()` 로 미룬다.
- 운영: 사용자 신고는 배치보다 **우선순위가 높다** — 실제 방문에서 확인된 오류이기 때문이다.
