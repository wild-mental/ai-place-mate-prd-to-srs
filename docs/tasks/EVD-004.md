## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 근거를 담은 카드가 생성된다
- Given: 이용자가 후보를 하나 선택하고
- When: 공유를 요청하면
- Then: 선정 이유와 근거를 담은 카드가 이미지 또는 링크로 생성된다. **생성 p95 ≤ 3,000ms · 공유 카드 생성률 ≥ 60% (US-3 AC3)**

Scenario 2 (실패 흐름): 근거 4항목이 없으면 카드를 만들지 않는다
- Given: 근거 4항목 중 하나가 누락된 후보 id가 주어지고
- When: 공유 카드를 요청하면
- Then: 이미지를 생성하지 않고 **400**을 반환한다. 빈 이미지나 플레이스홀더를 반환해서는 안 된다. **근거 없는 카드 0건 (§6.3-2)**

## ⚙️ Technical & Non-Functional Constraints
- 성능: **REQ-FUNC-005** 생성 p95 ≤ 3,000ms. GET 캐시가 가능한 유일한 경로이므로 캐시 헤더를 반드시 설정한다.
- 기술 제약: **C-TEC-002** 캐시 가능한 GET이므로 Server Action이 아니라 **Route Handler**로 구현한다(LIM-T04).
- 설계 원칙: 카드는 **근거를 담는 그릇**이지 홍보물이 아니다. 판정형 문구가 카드에 들어가지 않아야 한다.
