## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 인당 예상가가 범위로 표기된다
- Given: 이용자가 인당 예산 상한을 입력한 상태에서
- When: 후보 목록을 요청하면
- Then: 모든 후보 카드에 인당 예상가와 오차 범위가 표시된다. **표기율 100% · 범위 폭 ≤ ±20% (US-1 AC1)**

Scenario 2: 예산 초과 매장이 요약으로 밀린다
- Given: 예산 상한이 2만원이고 초과 매장이 존재하면
- When: 필터가 적용되면
- Then: 해당 매장은 기본 결과에서 제외되고 '예산 초과 N곳'으로만 요약된다. **오탐률 ≤ 3% (US-1 AC2)**

Scenario 3 (실패 흐름): 가격 데이터가 부실하면 판정하지 않는다
- Given: `sampleSize < 5` 이거나 가격이 90일 초과 미갱신인 매장이 후보에 포함되고
- When: 예산 필터가 실행되면
- Then: 예상가 대신 **'가격 확인 필요'** 로 표기하고 **판정 대상에서 제외**한다. 후보에서 빼면 커버리지 부족이 '결과 없음'으로 보인다. **예상가 오표기 0건 · 제외 사유 표기율 100% (US-1 AC6)**

Scenario 4 (실패 흐름): 범위 폭이 기준을 넘으면 표기하지 않는다
- Given: 추정 범위 폭이 ±20%를 넘는 상태에서
- When: 표기를 시도하면
- Then: 표기하지 않고 표본 추가 수집 큐로 넘긴다. 신뢰할 수 없는 범위를 내보내면 안 된다.

## ⚙️ Technical & Non-Functional Constraints
- 성능: **REQ-NF-001a** 예산 안에서 동작해야 한다. 추정은 색인 조회 결과 위의 순수 계산으로 두고 추가 왕복을 만들지 않는다.
- 품질: **보조 5** 예상가 오차 ±10% 내 비율 80%. `submitPriceFeedback` 의 편차 기록이 이 지표를 만든다.
- 설계 원칙: **단일 값 금지** — `PriceProfile` 은 범위만 저장한다(SRS §6.2). 평균 하나만 보여 주면 C2의 신뢰가 형성되지 않는다.
