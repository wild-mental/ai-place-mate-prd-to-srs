## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 프로필이 저장되고 재편집된다
- Given: 프로필 작성이 완료된 상태에서
- When: 사장이 내용을 갱신하려 하면
- Then: 기존 항목을 1회 클릭으로 불러와 수정할 수 있다. **프로필 갱신율 ≥ 70% (US-5 AC3)**

Scenario 2 (실패 흐름): 근거 없는 강점 문구가 저장되지 않는다
- Given: 사장이 등록된 사실 속성으로 뒷받침되지 않는 표현을 입력하고
- When: 저장을 시도하면
- Then: 해당 문구를 **저장하지 않고** 근거가 될 속성 등록을 안내한다. **근거 없는 제안 문구 0건 (US-5 AC4)**

Scenario 3 (실패 흐름): 타 매장 프로필을 저장할 수 없다
- Given: 가맹 A 세션으로
- When: 가맹 B의 프로필 저장을 시도하면
- Then: 인가 확인에서 거부되고 RLS가 2차로 막는다.

## ⚙️ Technical & Non-Functional Constraints
- 설계 원칙: **근거 없는 문구 0건**(§6.3-2) — 제안이 광고로 읽히지 않게 하는 유일한 장치다.
- 보안: **SRS §6.1 규약 ②** Server Action은 공개 엔드포인트와 동등 — 인가를 첫 줄에서 확인한다.
- 성능: 저장 후 `updateTag` 로 캐시를 무효화한다. 오래된 프로필이 소환 매칭에 쓰이면 안 된다.
