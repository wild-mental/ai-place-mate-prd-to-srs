## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 90일 초과 속성이 STALE로 전환된다
- Given: `verifiedAt` 이 91일 전인 속성이 있고
- When: 야간 스캔이 실행되면
- Then: `status = STALE` 로 전환되고 `ReverifyTask` 가 생성된다. 89일 건은 전환되지 않아야 한다. **경계 오판 0건**

Scenario 2: 초과 비율이 높으면 우선순위가 올라간다
- Given: 90일 초과 속성 비율이 25%인 상태에서
- When: 스캔이 완료되면
- Then: 재확인 큐 우선순위가 상향되고 알림이 발송된다. **임계 20% (REQ-NF-008)**

Scenario 3 (실패 흐름): Cron 실행 실패가 조용히 넘어가지 않는다
- Given: 스캔 중 예외가 발생한 상태에서
- When: 실행이 종료되면
- Then: 실패가 기록되고 마지막 성공 시각이 갱신되지 않는다. `REL-001` 이 24시간 초과를 감지해 알린다. **무증상 중단 0건 (R-T3)**

## ⚙️ Technical & Non-Functional Constraints
- 기술 제약: **D-05 · REQ-TEC-013** 상시 스케줄러를 두지 않는다. Vercel Cron → Route Handler로만 구현하고 외부 호출을 거부한다.
- 신뢰성: **REQ-NF-008** 90일 초과 시 경고 표기 필수. 스캔은 매일 1회 실행되고 **실행 실패 시 알림**이 발송되어야 한다.
- 성능: 야간 배치이므로 사용자 요청 경로와 분리된다. 다만 대량 갱신이 커넥션 풀을 잠식하지 않도록 배치 크기를 제한한다 (R-T2).
