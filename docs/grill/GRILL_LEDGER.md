## 재개 지점 — T3 카피 규약 (질문 준비 완료 · 미응답)

> 세션 1은 여기서 멈췄다. 사용자가 질문에 답하지 않고 **설명을 더 요청한 상태**로 종료했다.
> 재개 시 아래 질문을 그대로 다시 열되, **먼저 무엇을 더 설명할지 물은 뒤** 진행한다.

### 왜 T3이 필요한가

화면에 들어갈 **한국어 문장을 누가 정하는가**가 비어 있다. `UX-006`은 "판정형 표현 배제", `UX-004`는 "시스템 탓을 사용자에게 돌리지 않는다"라고만 적혀 있어, 에이전트가 착수하면 문구를 전부 창작한다. **프로토타입의 시각 인상은 레이아웃보다 문구가 좌우한다.**

특히 **선정 이유 1줄**(카드 슬롯 ② · 명세 §2.1)이 이 제품의 핵심 문장이다. 걸린 조건 셋:

| 조건 | 근거 |
| --- | --- |
| 판정하지 않는다 — "좋습니다" "추천합니다" 금지 | SRS §6.3-4 · US-3 AC2 `판정형 문구 0건` |
| 등록된 속성에 근거해야 한다 | SRS §6.3-2 |
| 남에게 보여 줄 수 있어야 한다 (C1의 Job) | PRD 페르소나 C1 |

### T3-a — 선정 이유 1줄의 문장 틀

| 안 | 내용 | 예시 | trade-off |
| --- | --- | --- | --- |
| **A (권장)** | **속성 나열 + 충족 개수** | `1인석 6석 · 21시까지 영업 — 조건 3개 중 3개 충족` | 판정 여지가 원천적으로 없다. 속성이 없으면 문장이 안 만들어져 '근거 없는 카드 금지'가 자동으로 지켜진다. 기계적으로 읽힐 수 있다 |
| B | 조건 매칭 서술형 | `혼자 앉기 편한 1인석이 6석 있습니다` | 읽기 좋으나 '편한' 같은 판정어가 스며든다. 픽스처 12장을 에이전트가 각각 작문 → 톤이 흔들린다 |
| C | 속성만 나열 | `1인석 6석 · 21시까지 영업` | 가장 짧다. 카드 슬롯 ③(근거 속성 칩)과 중복되고, 3개 중 2개만 맞은 후보를 구분할 수 없다 |

**권장 근거** — A는 에이전트가 문장을 창작할 자리를 없앤다. 픽스처 12장이 같은 틀을 쓴다.

### T3-b — 빈·오류 화면(S6·S7·S8) 문구의 확정 수준

| 안 | 내용 | trade-off |
| --- | --- | --- |
| **A (권장)** | **전문 확정** — 명세에 실제 문장을 적어 두고 에이전트는 복사만 | 톤이 흔들리지 않고, 문구 검토를 코드 없이 문서에서 끝낸다. 지금 15분 더 쓰고 D4에서 반나절 아낀다 |
| B | 톤 규칙만 (원칙 3~4개) | 유연하나 볼 문구가 즉석에서 정해진다 — '눈으로 확인'이라는 목적과 어긋난다 |
| C | 플레이스홀더 | 가장 빠르나 `UX-004`의 톤 체크박스를 판정할 수 없다 |

### 사용자가 보류한 지점 — 재개 시 먼저 확인할 것

사용자는 T3-a·T3-b 두 질문을 **한 번에 받고 보류**했다. 재개 시 다음 중 무엇이 걸렸는지 먼저 묻는다.

- 세 선택지의 차이가 안 와닿는가 → 카드 12장에 각각 적용한 예시로 풀어 준다
- "선정 이유 1줄"이 무엇인지 → 명세 §2.1 카드 슬롯 ②
- **"조건 3개 중 2개 충족"을 노출하면 후보가 약해 보이지 않나** → 실질 논점. 필요하면 T3-a의 네 번째 안으로 "충족만 표기" 검토
- 한 번에 둘을 물어서 → **T3-a·T3-b를 나눠서 하나씩** 진행
- T3보다 T4(색·폰트)를 먼저 보고 싶은가 → 순서 교체 가능 (T3·T4는 서로 의존하지 않음)
- 문구를 에이전트가 초안으로 뽑아 오게 하고 고르고 싶은가 → 가능

> **교훈** — 이 세션에서 두 질문을 한 턴에 묶은 것이 보류를 불렀다. 재개 후에는 **한 턴에 한 질문**만 연다.

## 해소 기록

### T1 — 확인할 화면 상태 목록 (CORE · RESOLVED)

**문제** — 로컬 최소안의 상태 8종에, PRD가 `표기율 100%` 를 건 고지 요건 3건(US-1 AC2 예산 초과 요약 · US-2 AC2 유사 메뉴 대체 · US-2 AC4 반경 확대)이 빠져 있었다.

**결정** — 상태 8종은 그대로 두고, 셋을 **결과 화면에 얹히는 고지 배너 3종**으로 추가한다. 독립 상태로 쪼개지 않는 이유는 셋 다 정상 결과 위의 각주이고 **둘 이상이 동시에 성립**하기 때문이다. 확인용으로 동시 노출 프리셋(`?fixture=notices`) 1개를 둔다.

**비용** — +0.5d 이내. 화면 수는 늘지 않는다.

**반영** — 명세 §1 · 로컬 최소안 §4·§8 · 스킬 `401-prototype-visual-rules` · `CLAUDE.md` 라우팅 표

### T2 — 후보 카드 정보 구조 (CORE · RESOLVED)

**문제** — 카드에 담을 내용은 SRS·PRD가 확정했으나 **배치와 위계**가 비어 있었고, 근거 4항목 중 **'확인 주체'의 값 집합이 어느 문서에도 없었다.**

**결정**
- **카드 3장 + 하단 비교표.** 카드는 슬롯 5개 순서 고정, 비교표는 축 4개(인당가·대표메뉴·상황속성·확인일자)
- 390px 3열 문제는 **값 최대 5자 축약**으로 푼다 — 폰트 축소·가로 스크롤 대신
- **확인 주체 4종** — 매장 등록 · 후기 코멘트 · 운영자 검증 · 자동 수집. v0.1의 네 경로(`MCH-004`·`EVD-005`·`DAT-010`·`DAT-006`)와 1:1

**용어 고정 (전면)** — `이용자 확인` → **`후기 코멘트`**. `리뷰·별점·평점` 계열은 v0.2 연기 기능과 혼동되므로 쓰지 않는다.

**반영** — 명세 §2 · 스킬 `401` 3개 절 추가

### T4 — 디자인 토큰 실제 값 (CORE · RESOLVED · 자율 결정)

**브랜드 primary = `oklch(0.47 0.072 197)` 딥 틸.** 네이버 그린(`#03C75A`)을 쓰지 않는다 — 1차 유통 경로가 네이버 지도 탭이라(ADR-005) 같은 색이면 네이버 서비스로 오인된다. 채도를 낮춘 것은 '판정하지 않는다'(SRS §6.3-4)를 시각 언어에서도 지키기 위해서다.

**상태 4종 토큰** — `--notice`(고지 배너 · 오류색 아님) · `--warn`(90일 경과 · 앰버, 후보를 부정적으로 보이게 하지 않는 톤) · `--empty` · `--evidence`(확인 일자·주체).

**라이트 전용.** 다크 모드는 로컬 최소안 §3에서 잘라냈다. shadcn이 넣은 `.dark` 블록은 `class="dark"` 를 붙이지 않으므로 무효다.

**next/font 제거 · 시스템 한글 스택.** `create-next-app` 이 넣은 Geist는 한글 글리프가 없고 next/font는 빌드 시 Google Fonts를 받는다 — 로컬 최소안 §0의 '외부 의존 0건'과 어긋난다. `-apple-system → Apple SD Gothic Neo → Pretendard → Malgun Gothic → Noto Sans KR` 스택으로 바꿨다. next/font 최적화는 `INF-002` 본 착수 범위다.

### T5 — shadcn 컴포넌트 인벤토리 (MINOR · RESOLVED · 자율 결정)

상태 8종 + 배너 3종을 그리는 데 필요한 최소 집합이다. **이 목록 밖 컴포넌트를 자체 구현하지 않는다**(D-08 · REQ-TEC-007). 더 필요하면 만들지 말고 `shadcn add` 로 설치하고 이 목록에 더한다.

### T3 — 카피 규약 (CORE · RESOLVED · 자율 결정)

**선정 이유 1줄의 문장 틀을 고정했다** — `<속성 나열> — 조건 N개 중 M개 충족`.
판정어를 넣을 자리가 없게 만든 틀이다. 서술형으로 두면 '편한' '좋은' 같은 판정어가 스며들고, 픽스처 12장을 에이전트가 각각 작문하면서 톤이 흔들린다.
**미충족 개수를 숨기지 않는다** — `3개 중 2개 충족`을 그대로 쓴다. 감추면 방문 후 불일치(현행 35%)로 돌아온다.

**상태·배너 문구는 전문을 명세에 박았다.** 지금 15분 더 쓰고 구현에서 반나절 아낀다. 쓰지 않는 표현도 함께 적었다 — `오류가 발생했습니다`(책임 모호) · `잘못된 입력입니다`(사용자 탓) · `검색 결과가 없습니다`(다음 행동 없음).

### T6 — 픽스처 데이터의 실체 (CORE · RESOLVED · 자율 결정)

강남역 반경 1km · 합성 매장 3곳. **확인 이력을 속성 단위로 둔 것이 이 결정의 핵심이다.**
US-3 AC2가 "어떤 속성이 90일 이상 갱신되지 않았고"라고 쓰므로 확인은 카드가 아니라 속성에 붙는다. 그 덕에 카드 3장으로 **확인 주체 4종이 한 화면에 다 보인다** — 카드당 1건이면 3종이 한계였다.

### T7 — 확인 도구 (MINOR · RESOLVED · 자율 결정)
